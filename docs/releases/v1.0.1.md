**An oversized file is named again.** zoxy refuses a config that names
a file too large to read. 1.0.0 stopped saying which file when it was a
listener's certificate or key, and 1.0.1 names it again. It also names
an oversized body file or CA bundle, which no earlier release did.
Nothing else changes.

## Fixes

- **An oversized file is named.** zoxy reads each certificate, key, body
  file and CA bundle a config names whole at startup, up to a limit:
  256 KiB for a listener's certificate or key, and 1 MiB for a body file
  or a CA bundle. A file over its limit refuses the config, and 1.0.0's
  error named only the verdict: `ListenerTlsFileUnreadable`,
  `BodyOverLimit`, `ClusterTlsCaUnreadable` or
  `ListenerTlsClientCaUnreadable`. The line before it now says which
  file, and why:

  ```
  zoxy: cannot read '/etc/zoxy/cert.pem': larger than 262144 bytes
  zoxy: invalid config '/etc/zoxy/zoxy.json': ListenerTlsFileUnreadable
  ```

  0.12.1 named an oversized certificate or key, though not a body file
  or CA bundle. 1.0.0 moved the certificate read into the config loader
  and lost that line. A missing or unreadable file has been named all
  along.

## Under the hood

- **The live gate reads what `--check` says when it refuses.** It runs
  `--check` on a config that the loader's address check should refuse,
  but it read only the exit code and whether a budget reached stdout.
  Since listeners were tagged, that config had been refused earlier, for
  an unknown key, so the gate never reached the check it was written
  for. It now pins all of what each refusal writes to stderr, and adds a
  config with an oversized certificate, whose refusal must name the
  file.

## Checked against

- **The gates.** Both changes passed the unit and fuzz corpus, the lint,
  4,096 simulator seeds with the census, and the live gate in both the
  default and the shipped ReleaseSafe build.
- **The soak.** A run on this release's code passed: 4 × 1,000,000
  seeds, 504,000,001 to 508,000,000,
  [run 44667926027](https://github.com/zoxy-io/zoxy/actions/runs/44667926027).

## Upgrading

Replace the binary. A config 1.0.0 loads, 1.0.1 loads the same way. A
config 1.0.0 refuses, 1.0.1 refuses with the same error and exit code;
the only difference is the new line naming an oversized file.
