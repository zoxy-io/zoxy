**zoxy now reaches origins over HTTP/2 and over TLS, and gRPC works end
to end.** Each new feature is off until a cluster asks for it. A config
that asks for none of them reserves nothing new, with two exceptions:

- A listener that speaks HTTP/2 now passes an origin's trailers on to
  its clients; 0.10.x dropped them.
- One parse verdict changed, under [Fixes](#fixes).

## HTTP/2 to the origin, and gRPC

A cluster can now speak HTTP/2 to its origins. `"protocol": "h2c"` uses
prior knowledge in the clear (RFC 9113 §3.3), and `"h2"` uses TLS, below.

```json
"grpc": {
    "endpoints": ["10.0.0.5:50051", "10.0.0.6:50051"],
    "protocol": "h2c",
    "check": { "type": "grpc" }
}
```

Its requests share pooled connections, each request on a stream of its
own, so they no longer take a socket apiece. That is what gRPC needs:

- **Trailers.** An origin's trailer section reaches the client, whichever
  protocol the origin speaks. An HTTP/2 client gets it as the stream's
  trailing HEADERS, and an HTTP/1.1 client as a chunked body's trailer
  section. So `grpc-status` arrives where a gRPC client looks for it.
  0.10.x dropped trailers on the way to an HTTP/2 client, even from an
  HTTP/1.1 origin.
- **`te: trailers`** reaches an HTTP/2 origin. It is still hop-by-hop
  toward an HTTP/1.1 one.
- **Streaming in both directions.** The origin may answer while the
  request is still arriving, and the call ends once both halves have.
  `idle_ms` bounds a silence on it, and is refreshed by every message
  either way.

Either client protocol reaches an HTTP/2 cluster. The exchange is
written out as an HTTP/1.1 head and read back, as with HTTP/2 clients in
0.10.0, so every rule a request is held to is still stated once.

Two pools carry it, both zero unless a cluster speaks HTTP/2:

- `limits.h2_origin_connections`: two per HTTP/2 endpoint by default.
- `limits.h2_origin_streams`: requests on them at once, `upstream_slots`
  by default and never more.

A request that finds neither free is answered `503`. It is counted in
`zoxy_l7_shed_h2_origin_connections` or
`zoxy_l7_shed_h2_origin_streams`.

A failure on an origin stream fails that request alone, as a socket
error would: a refused dial is a `502`, and a silent origin a `504`. A
stream the origin resets, or refuses past its `GOAWAY`, gets the free
replay a stale pooled connection gets. An idle origin connection is told
`GOAWAY` and closed.

Not reachable from an HTTP/2 cluster, and refused by the loader:

- an `l4` listener (it relays bytes);
- an upgrade such as WebSocket (HTTP/2 has no `101`);
- an `http` health check (that prober speaks HTTP/1.1). Use `tcp` or
  `grpc`.

## TLS to the origin

A `tls` block on a cluster makes zoxy originate TLS to its origins:

- with `"protocol": "h2"`, HTTP/2 over TLS;
- with `http1`, the default, plain HTTPS origins.

```json
"billing": {
    "endpoints": ["10.0.0.7:443", "10.0.0.8:443"],
    "tls": { "server_name": "billing.internal", "ca": { "path": "/etc/zoxy/internal-ca.pem" } }
}
```

Every handshake is verified, and verification cannot be turned off:

- The chain must reach a certificate in the `ca` bundle, through CAs
  only.
- The leaf must carry `server_name` in its subjectAltName (RFC 9525; a
  common name alone does not count).
- `server_name` is also the SNI sent. It is configured because an
  endpoint address is not an identity.
- The bundle is read once at load, so a missing or empty file stops the
  config, not the first request.
- ALPN offers the cluster's protocol, `h2` or `http/1.1`. An HTTPS origin
  may also select nothing.

A failed handshake is a `502`. It is counted in
`zoxy_h2_origin_tls_failed` or `zoxy_upstream_tls_failed`, and is not
retried on another endpoint, because the dial itself succeeded. An HTTPS
origin's connection is verified once, then parked and reused like any
other, without a second handshake. `zoxy_upstream_tls_handshakes` shows
how often reuse saved one.

`limits.upstream_tls_sessions` bounds the HTTPS sessions. Each session
holds about 110 KiB. The default is 16 per HTTPS endpoint, within
`upstream_slots`. A new connection with no session free is answered
`503`, counted in `zoxy_l7_shed_upstream_tls`. Listener engines, `h2`
origin connections and HTTPS sessions share the one fixed libcrypto heap
of 1,024 sessions, and the loader refuses a config that would overrun
it.

Not carried over TLS to an HTTPS origin yet, and refused by the loader:
`http` health checks (use `tcp`), upgrades, and `l4` listeners.
Certificates' `pathLenConstraint`, keyUsage and extendedKeyUsage are not
checked; the anchors are your own CAs.

## gRPC health checks

An HTTP/2 cluster can check its origins with the standard gRPC health
service:

```json
"check": { "type": "grpc", "service": "greeter.Greeter" }
```

- **The call.** The probe calls `grpc.health.v1.Health/Check` on a stream
  of the cluster's own pooled connections, over its TLS when it has one.
- **Pass.** It passes only on `:status` 200, a `SERVING` answer and
  `grpc-status: 0`.
- **`service`.** It is optional; without it, the probe asks about the
  server as a whole.
- **Pool full.** If the pool has no connection to the endpoint and no
  room for one, the probe is skipped rather than failed, since that limit
  is zoxy's, not the origin's. Skips are counted in
  `zoxy_health_probes_skipped`. If that counter keeps rising,
  `limits.h2_origin_connections` is too small.

## gRPC deadlines

A gRPC call's own `grpc-timeout` is now honored. It arms the same
per-exchange deadline `request_ms` does, and replaces it when it is
earlier or when `request_ms` is off.

- **Expiry.** When the deadline runs out before the origin answers, the
  client gets `grpc-status: 4` (DEADLINE_EXCEEDED). It does not get a
  `504`, which a gRPC client reads as UNAVAILABLE and may retry. The
  expiry is counted in `zoxy_l7_grpc_deadline_exceeded`.
- **Passive ejection.** A client's deadline is never held against the
  endpoint, so a client with tight deadlines cannot eject a healthy
  origin.
- **The origin.** The header still reaches it unchanged.

## Fixes

**A full buffer of malformed request head now answers `400`.** Suppose a
request head never ends (no blank line) and starts with a byte no method
starts with. If it filled the head buffer, it was answered as oversize,
`414` or `431`, rather than the `400` that the same bytes get when they
arrive whole. The fuzzer found it. Every malformed head now gets the
same answer however it arrives.

## Checked against

- **The gates.** Every change passed the unit and fuzz corpus, the lint,
  4,096 simulator seeds with the census, and the live gate in both the
  default and the shipped ReleaseSafe build.
- **The live gate.** It now drives:
  - an h2c origin, with gRPC-shaped answers and trailers;
  - an `h2` origin and an HTTPS origin over verified TLS, by looping
    through zoxy's own TLS listeners, each with a misnamed twin that must
    be refused;
  - a `grpc` health check.
- **h2spec.** It matched DESIGN §12's recorded deviations: 145 cases, 1
  recorded failure, on h2c.
- **Hand runs** against Node's `http2` server, over h2c and TLS:
  - large bodies, multiplexed, and 1 MB uploads went whole;
  - a wrong `server_name` gave a 502;
  - the drain was clean.
- **The soak.** A nightly run on this release's code passed: 4 × 1,000,000
  seeds, [run 44250341915](https://github.com/zoxy-io/zoxy/actions/runs/44250341915).
- **Known gap.** The simulator builds no HTTP/2 or TLS origin yet, so
  those paths are held by the directed scenarios, the live gate and the
  assertions, not by seeded sweeps.

## Upgrading

Replace the binary. No existing config key, metric name or default
moved, and `--check` prices a config that uses none of this exactly as
0.10.1 did.

New config keys:
- `clusters.*.protocol`: `http1`, `h2c` or `h2`;
- `clusters.*.tls`;
- `check.type` `"grpc"` and `check.service`;
- `limits.h2_origin_connections`, `limits.h2_origin_streams` and
  `limits.upstream_tls_sessions`.

The startup banner gains lines for the new pools, which read zero unless
used. If any cluster has `tls`, the libcrypto heap is installed even when
no listener terminates TLS.

New counters:
- `h2_origin_connections`, `h2_origin_connect_failed`,
  `h2_origin_idle_closed`, `h2_origin_streams_reset`,
  `h2_origin_refused_heads`, `h2_origin_refused_answers`,
  `h2_origin_tls_failed`;
- `l7_shed_h2_origin_connections`, `l7_shed_h2_origin_streams`;
- `upstream_tls_handshakes`, `upstream_tls_failed`,
  `l7_shed_upstream_tls`;
- `health_probes_skipped`, `l7_grpc_deadline_exceeded`.
