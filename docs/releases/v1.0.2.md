**A certificate is refused beside a key that is not its own.** Every
release that terminates TLS loaded such a pair, passed `--check`, and
then failed every handshake on it. That looks like broken clients, not
a wrong config. 1.0.2 refuses the pair at startup and names it. The
check costs a little at startup; see [Upgrading](#upgrading).

## Fixes

- **A mismatched certificate and key are refused at startup.** A
  listener's `cert` and `key`, and each pair in its `certificates`, are
  read separately, and until now nothing compared them. When the key
  was not the certificate's, the config loaded, `zoxy --check` passed,
  and every handshake on that listener failed. The client checks the
  server's signature against the certificate, and a signature made by
  another key fails that check. The client saw a handshake error, and
  zoxy counted it in `zoxy_tls_handshake_failed`.

  The key now signs once at load, and zoxy checks that signature against
  the certificate the way a client would. A pair that fails stops
  startup, and `--check` exits 1:

  ```
  zoxy: listener 0 cannot use '/etc/zoxy/cert.pem' + '/etc/zoxy/key.pem': CertificateKeyMismatch
  ```

  Every ECDSA key is checked, and so is every 2048-, 3072- or 4096-bit
  RSA key. An RSA key of another size is loaded unchecked, as before:
  real clients accept it, but the verifier zoxy checks with cannot.

## Under the hood

- **The live gate pins this refusal too.** Its `--check` pre-flight now
  includes a certificate beside another certificate's key. Unlike the
  other pinned refusals, this one is priced: the config loads, and it is
  the startup that refuses it.

## Checked against

- **The gates.** The change passed the unit and fuzz corpus, the lint,
  the libcrypto heap proof, 4,096 simulator seeds with the census, and
  the live gate in both the default and the shipped ReleaseSafe build.
- **The tests.** They cover a matched pair of every key kind and RSA
  size zoxy ships fixtures for (P-256, P-384, RSA-2048, RSA-3065,
  RSA-4096), and nine mismatches: the same kind and size, another size,
  and another kind of key. Each was checked to fail with its part of the
  fix taken out.
- **The soak.** A run on this release's code passed: 4 × 1,000,000
  seeds, 512,000,001 to 516,000,000,
  [run 44693419791](https://github.com/zoxy-io/zoxy/actions/runs/44693419791).

## Upgrading

Run `zoxy --check` on your config before you replace the binary. A
certificate beside a key that is not its own is now refused. As 1.0.0's
notes allow, this is a config that only ever loaded by mistake: no
client that checks the server's signature, as every TLS 1.3 client
does, ever completed a handshake on it. Nothing that worked stops
working.

- **Startup.** Each certificate pair now signs once at startup. That
  takes microseconds for an ECDSA key and about 5 ms for an RSA-4096
  key, so a process loading the 256-certificate maximum, all RSA-4096,
  starts about 1.2 seconds later.
- **Memory.** With TLS configured, resident memory right after startup
  reads about 1 MB higher. libcrypto's setup for the first signature
  now happens at startup rather than on the first handshake. After the
  first handshakes, memory is where it was.
