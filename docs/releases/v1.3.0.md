**zoxy 1.3: origins by DNS name.** An endpoint may now be written
`name:port`. By default the name is resolved once, at startup, by the
system's resolver. A cluster with a `dns` block instead follows its
names while it serves: zoxy's own resolver asks the names again as their
TTLs run out, and the cluster's endpoints follow the answers.

A config without names needs nothing: replace the binary. It serves what
1.2.2 served, and the new counters stay at zero. Upgrading describes
what moved for a build on the library.

## Endpoints by DNS name (#480)

```json
"endpoints": ["api.internal:8080", { "address": "api-v6.internal:8080", "family": "ipv6" }]
```

- **Resolved once, at startup,** through the system's resolver:
  getaddrinfo where there is one, with the hosts file and `resolv.conf`'s
  search domains, as any other program on the machine finds the name.
  Each name's addresses are printed on stderr before the banner:
  `zoxy: api.internal:8080 is 10.0.0.1:8080 10.0.0.2:8080`.
- **Every address** becomes an endpoint with the entry's `weight` and
  `priority`, in the entry's place; a name's own addresses go IPv4 first,
  then in address order.
- **`family`**, a new key on the object form, says which: `ipv4` (the
  default; A records), `ipv6` (AAAA) or `any`. It is refused beside an
  address (`EndpointFamilyWithoutName`).
- **One address, once.** In a cluster that names a host, two entries
  giving the same address make one endpoint, holding the stronger claim:
  the lower `priority`, then the higher `weight`. A cluster of addresses
  alone keeps what it states, as before.
- **A name that does not resolve** stops the start
  (`EndpointNameUnresolved`), and `--check` exits `2` on it: the config
  may be right on a machine whose resolver knows the name.
- Binds stay literal: listeners, `quic` and `admin`.

## Following a name while serving (#481)

```json
"clusters": { "api": {
    "endpoints": ["api.internal:8080", "10.0.9.1:8080"],
    "dns": { "refresh_min_ms": 1000, "refresh_max_ms": 60000, "addresses_max": 16 } } },
"resolver": { "nameservers": ["10.96.0.10"], "timeout_ms": 2000 }
```

DESIGN §7's "Names while serving" has the whole design, and the manual's
"Following a name while serving" the operator's view.

- **Who is asked.** The `resolver` block's nameservers, over UDP, in
  order, the next when one times out or answers SERVFAIL or REFUSED; a
  nameserver without a port is on 53. Without the block, the nameservers
  `/etc/resolv.conf` names. Names are asked as written: no search
  domains, no hosts file.
- **At startup** each name is asked of the same nameservers, in the same
  wire format, before the config is resolved — so a cluster never starts
  from an answer it would not get again. A name with no address stops
  the start, and `--check` exits `2`.
- **While serving** each name is asked again as its answer's TTL runs
  out, held between `refresh_min_ms` (1000 by default) and
  `refresh_max_ms` (60000), plus up to a tenth more, drawn, so processes
  started together do not ask together. The cluster's endpoints become
  its own IP addresses and every name's latest, each once, through
  1.1's endpoint slots (#428): an address that leaves drains, one that
  arrives is probed first on a health-checked cluster, and one that
  stays keeps its slot, its health and its pooled connections.
- **When DNS fails** a name keeps the addresses it had: every nameserver
  timing out, NXDOMAIN, or an answer that did not fit 1232 octets. An
  answer with no address of the name's family empties it; a set that
  would leave the cluster with no endpoint is refused, and the cluster
  keeps the one it has.
- **Replies are checked, not signed.** One counts only from the
  nameserver asked, under the query's ID, echoing its question, and only
  for the name or the end of a CNAME chain from it. A chain that ends at
  no record asks the next nameserver.
- **Room.** `addresses_max` (16, at most 64) caps one name's addresses in
  each family; an answer with more keeps the first in address order. The
  cluster's endpoint tables are sized for its addresses and twice that
  per name and family, so a whole new set fits while the last drains.

### Limits of this release

- **No TCP fallback.** A truncated answer fails the query; `addresses_max`
  keeps a real one within a datagram.
- **No DNSSEC.** Point the resolver at a local or cluster DNS server. An
  off-path forger faces a 16-bit ID and a source port the kernel picks
  once for the process.
- **No search domains while serving.** Write the full name.
- **The address is the endpoint's identity**, as before: the health
  check's `Host`, the access log and the per-endpoint metrics name the
  address, not the name.
- **A cluster that follows names** takes no `endpoint_slots` and no
  `unix:` endpoint, and a build cannot replace its set itself
  (`Startup.endpointSet` answers null): the resolver writes it.

## The stock binary

- **The banner** gains a line, `dns resolver`, which reads `0 B (0
  queries, ...)` without a cluster that follows names.
- **`--check`** exits `2` for a name this machine cannot resolve, and
  says so in `--help`.
- **Metrics.** 11 new counters, listed under Upgrading, each rendered at
  zero without a cluster that follows names.
- **The JSON Schema** gains an endpoint's `name:port` spelling and its
  `family`, a cluster's `dns` block (`refresh_min_ms`, `refresh_max_ms`,
  `addresses_max`), and the top-level `resolver` block (`nameservers`,
  `timeout_ms`).

## Checked against

- **The gates.** Every change passed the unit and fuzz corpus, the lint,
  4,096 simulator seeds with the census, and the live gate in both the
  default and the shipped ReleaseSafe build, on CI's x86-64 and arm64
  Linux runners.
  - The census: 130 counters fired, 63 exempt — the 11 new `dns_*`
    counters among them, since the sweep's clusters follow no name;
    23 extension counters fired; 12 seam operations, 1 exempt.
  - Three new fuzz targets: DNS replies, an endpoint's DNS name, and the
    merge of a cluster's addresses. The config's seed carries names.
- **The resolver under the simulator** (`src/dns/resolver_test.zig`):
  scripted nameservers on SimIo's datagrams — a name that moves,
  failover, NXDOMAIN, forged IDs, truncation, TTL pacing between the
  floor and the ceiling, a refused set, an answer past its room, every
  nameserver failing, a drain mid-round, rotating sets that must end
  where the answers did, and 24 seeds of the datagram adversary
  (drops, duplicates, corruption, delays, rebinding), through which the
  set holds only what was answered.
- **The live gate** gained two legs.
  - The sticky cluster's endpoint is `localhost`, and `--check` on an
    unresolvable `.invalid` name must exit `2` with the resolver's reason.
  - A proxy of its own follows a name the harness's nameserver answers
    over real UDP. That nameserver writes its replies with its own few
    lines of RFC 1035, not zoxy's codec. The start resolves the name, a
    request reaches the origin through it, the name moves, and the
    proxy takes exactly one new set and drains.
- **Not run for this release:** h2spec and h3spec on Linux, and the
  Tier-1 bench. Neither conformance binary was on the release machine,
  and nothing in 1.3.0 touches HTTP/2, QUIC or HTTP/3 framing. A config
  that follows no name runs 1.2.2's serving path: the resolver arms
  nothing and is asked nothing until a cluster declares `dns`.
  - h2spec 2.6.0 over h2c on macOS, where kqueue's timing makes its
    timeout cases flaky, failed 4 to 13 of 146 cases across runs of
    1.2.2 and 1.3.0 alike.

## Upgrading

Replace the binary. A config 1.2.2 loads, 1.3.0 loads the same way.

A build on the library moves with it:

- **`Options`** gains `resolver` (`?Options.Resolver`, default null) and
  `Cluster.dns` (`?Options.Cluster.Dns`, default null). Struct literals
  need no change.
- **New exports**, under `zoxy.dns`: `host` (an endpoint name's canonical
  form, `Family`), `endpoints` (a name's address order, the merge),
  `message` (the DNS codec, and the responder half a test server writes
  with) and `startup` (`resolveNames`, what `App` runs before step zero).
- **`zoxy.constants`**: `inFlightOps`, `cqFillFits` and
  `completionQueueDepthFor` take the resolver's ops
  (`constants.resolverOps`) before the fill, and `fdsRequired` the
  resolver's sockets last; `PoolSizes` gains `resolver_bytes`. A build
  that calls them passes 0 for a config that follows no name.
- **`App.serve`'s error set** gains `EndpointNameUnresolved`, which
  `App.check` answers with `does_not_fit`, and both, with
  `config.ValidationError`, gain the new refusals:
  - `ResolverMissing`, `ResolverUnused`
  - `ResolverNameserversOutOfRange`, `ResolverNameserverPortZero`,
    `ResolverTimeoutOutOfRange`
  - `ClusterDnsNamesEmpty`, `ClusterDnsNameInvalid`,
    `ClusterDnsEndpointSlots`, `ClusterDnsUnixEndpoint`,
    `ClusterDnsRefreshOutOfRange`, `ClusterDnsAddressesMaxOutOfRange`,
    `ClusterDnsAddressInvalid`
- **New counters**, each at zero without a cluster that follows names:
  - `dns_queries_sent`, and one outcome each: `dns_answered`,
    `dns_nxdomain`, `dns_servfail`, `dns_truncated`, `dns_timed_out`,
    `dns_canceled`
  - `dns_replies_dropped`, `dns_answers_truncated`
  - `dns_updates_applied`, `dns_updates_refused`
