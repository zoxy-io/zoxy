**zoxy 1.3.1: fixes the simulator found.** The simulator now sweeps
HTTP/2 and HTTPS origins, mutual TLS, certificate choice by name, SNI
routing, DNS-following clusters and gRPC health checks (#486, #488).
Those sweeps found three defects in what 1.3.0 ships, plus several
smaller ones:

- a crash on the first replay to an HTTP/2 origin;
- mutual-TLS sessions that lost their client identity on resumption;
- a core-burning spin while closing an HTTP/2 origin connection whose
  timer completion never arrives.

Replace the binary; no config changes. A listener with `client_ca` no
longer resumes sessions; Upgrading says what that costs.

## Fixes

- **A replay to an HTTP/2 origin no longer crashes the process** (#275).
  A request whose first attempt on a pooled connection fails before any
  answer is replayed on a fresh one. To an HTTP/2 origin, that replay
  held the header scratch across its dial. A multiplexed dial renders at
  once and borrows the same scratch, so the first such replay failed an
  assertion. Release builds keep assertions, so the proxy exited. The
  borrow now ends before the dial.

- **A listener with `client_ca` resumes nothing** (#304). It still
  issued and opened session tickets. A ticket seals only the PSK, and a
  resumed TLS 1.3 handshake carries no CertificateRequest (RFC 8446
  §4.3.2). So a resumed session reached the origin with no
  `X-Client-Cert-SHA256`, and its policies with no client names, for as
  long as the ticket lived. On a `required` listener, that is a session
  which never proved the client's key. Such a listener's engines now get
  no ticket keys, over TCP and QUIC alike.

- **Closing an HTTP/2 origin connection cannot spin** (#275). A closing
  connection whose timer was still armed cancelled the timer again each
  time a cancel completed. A timer completion that never arrived made
  each cancel the next one's cause. The loop then spun at 100% of a core
  with no time passing, so the drain's backstop never fired. The close
  now cancels once and waits for the timer's own completion.

- **A refused client certificate is told why** (#304). A client refused
  for want of a certificate could see a reset instead of
  `certificate_required`. A TLS 1.3 client sends its first request
  straight after its Finished, and closing on that unread request is a
  reset that can overtake the alert. The close now lingers, as an HTTP
  close does: the write side ends, what arrives is discarded, and the
  client's own end, or the TLS phase's deadline, finishes it. An ALPN
  refusal takes the same path.

- **`zoxy_health_probe_deadline_raced` no longer counts a tie.** A
  `grpc` probe dials through the origin pool, which gives up at the
  cluster's connect budget. A check's `timeout_ms` defaults to that same
  budget. So against an unreachable endpoint, the verdict and the probe's
  deadline landed in one instant, and the counter took that for the
  late-cancel race it watches for (#130). With stock settings it climbed
  on every such probe. A deadline that fires in the instant its cancel
  went out is no longer counted. A late cancel, or none at all, still is.

- **A drain held by HTTP/2 origin connections says so.** The stuck-drain
  report never asked about origin connections or QUIC endpoints. A drain
  held there ended with only the loop watchdog's word. The report now
  names an `origins=` plane.

## Under the hood

- **A build that hands `Server.init` its own limits** gets an assertion
  that a relay half fits a whole ClientHello when a listener routes by
  SNI (#298). The loader already refused a narrower one
  (`LimitRelayBufferUnderSniRouting`). Limits passed in code skip the
  loader, and the first long hello was read past the buffer.
- **`zoxy.testing` grows** what the sweeps drive:
  - `HttpsOrigin`, an HTTP/1.1 origin behind TLS;
  - `Nameserver`, `Zone` and `Behavior`, scripted nameservers;
  - an HTTP/2 test origin that answers gRPC's health call
    (`health`, `grpc_serving`, `grpc_not_serving`);
  - more TLS fixtures: RSA, a P-256 and an RSA wildcard, and a client
    leaf.

  The TLS test client can narrow its signature offer (`SchemeOffer`).
  The QUIC test client now verifies the leaf's signature, and can name
  its server (`startNamed`).
- **The coverage report gates** (#487). `zig build coverage` lists every
  serving-path line the unit tests reach and the sweep does not. Each is
  now either swept or set apart with a reason in
  `scripts/sim_gap_exemptions.zig`. The report fails on a new line that
  is neither.

## Checked against

- **The gates.** Every change passed the unit and fuzz corpus, the lint,
  4,096 simulator seeds with the census, and the live gate in both the
  default and the shipped ReleaseSafe build.
- **The sweeps that found them.**
  - The first sweep over HTTP/2 origins failed on three seeds, one per
    defect: the spin on 728, the silent drain on 838, the replay crash on
    3023. The sweep has drawn more since, so those numbers name that
    sweep's schedules, not today's.
  - The resumption and the lost alert each have a directed test that
    fails with its fix removed: a verified client on a `client_ca`
    listener is issued no ticket, and a client refused for want of a
    certificate hears `certificate_required` though it already sent its
    request.
- **Sixteen times the gate's range.** Seeds 1..65,536 pass with the
  census holding, which is where the probe-race tie showed (19 firings,
  all on gRPC-probe seeds). A 1 ms offset between the two budgets removed
  every race. A prober that never cancels its deadline (#130 restored)
  still fires the counter 5,869 times in 4,096 seeds.

## Upgrading

Replace the binary; no config changes.

A listener with `client_ca` now runs a full handshake for every
connection, over TCP and QUIC, where a returning client used to resume.
The round trips are the same, since TLS 1.3 resumes in one as well. But
each handshake now sends the certificate chain again, signs again, and
verifies the client's chain again, so expect more TLS CPU and larger
handshakes from clients that reconnect often. That is the price of
every session proving its client's key. Listeners without `client_ca`
resume as before.

`zoxy_health_probe_deadline_raced` should now read near zero under the
default check timeout. A steady rise means probes that do not cancel
their deadlines.
