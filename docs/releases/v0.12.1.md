**A fix for a crash any client could trigger on one configuration.** On
an `l4` listener that routes by SNI to a cluster sending a PROXY header,
a ClientHello near 16 KiB made the proxy panic. Every release since
0.8.0 has it. If you run that combination, upgrade. This release also
closes a config hole, stops a false kernel-pressure signal on socket
files, and raises the connection ceiling.

## Fixes

- **An oversized ClientHello no longer crashes an SNI listener.** To
  pick a route, an `l4` listener with `routes` reads the client's hello
  into the relay buffer's client-to-upstream half. That read could fill
  the whole half: 16 KiB, at the default `relay_buffer_bytes`. A cluster
  with `"proxy_protocol": {"send": ...}` puts its header in front of the
  hello in the same half. With a hello that large there was no room for
  it, and the assertion that checks for room stopped the process. The
  release build keeps its assertions, so one connection was enough. The
  read now stops 107 bytes short of 16 KiB, which is room for any header
  zoxy sends. A hello still incomplete there is closed and counted in
  `zoxy_l4_sni_invalid`. Real hellos are 2–3 KiB, so only a padded one
  reaches the limit.
- **An SNI route can no longer reach an HTTP/2 or HTTPS cluster.** An
  `l4` listener relays bytes, so it cannot speak HTTP/2 to an `h2c` or
  `h2` origin or originate TLS for an HTTPS cluster. The loader refused
  that for a listener's `cluster`, but of a `routes` table it checked
  only the cluster connections are first admitted under: the catch-all
  route's, or the first route's. A config whose other routes named such
  a cluster loaded, and their connections were relayed as plain bytes.
  Every route is checked now.
- **Socket files no longer count as kernel pressure.** zoxy turns off
  Nagle (`TCP_NODELAY`) on every connection. Linux refuses that option
  on a Unix socket, and each refusal was counted in
  `zoxy_kernel_pressure_errors`. So every connection a `unix:` listener
  accepted or a `unix:` endpoint carried raised it. zoxy no longer asks
  a Unix socket for the option. If you alert on that counter and serve
  over socket files, expect it to drop to what it measures.

## A higher connection ceiling

The ring budget reserved a completion for each upstream slot, for an
idle timer that keep-alive never needed: one sweep timer reaps every
parked upstream connection. The budget now charges that one timer
instead. Each connection costs four completions rather than five, so
`limits.conn_slots`, `limits.upstream_slots` and `limits.relay_buffers`
now accept up to **14321**, up from 11457. The defaults do not move.
`zoxy --check` reports fewer in-flight ring ops for a config with
upstream slots: one fewer per slot, plus one for the sweep.

## Under the hood

- `docs/DESIGN.md` is rewritten as the 1.0 design: shorter, with
  diagrams, and checked against the code. The implementation journal
  that sat beside it is gone, and what still holds of it moved into
  DESIGN.md.
- The README's SNI matching order is a bulleted list, so zoxy.io can
  render it.

## Upgrading

Replace the binary. One config that 0.12.0 accepted is now refused: an
SNI route to an `h2c`, `h2` or HTTPS cluster fails at load with
`ClusterH2cOnL4Listener` or `ClusterTlsOnL4Listener`. Such a route never
worked. Point it at a cluster that speaks plain bytes to its origin, or
route that traffic through an `http` listener.

An SNI listener now refuses a ClientHello longer than 16,277 bytes.

Roll the binary forward before raising a pool past 11457: 0.12.0 refuses
those limits.
