No change to how zoxy proxies anything. `src/` is untouched since 0.5.1 — this
release is entirely about what gets built, and for whom.

## Intel Macs have binaries again

**`x86_64-macos` is back, for the first time since 0.2.0.** If you have been
building from source on an Intel Mac, you no longer have to, and `brew` now has
something to give you: the formula gains an `on_intel` branch it has never had.

It went missing because a C dependency made cross-compilation impossible, and
building it natively needs an Intel macOS runner GitHub no longer offers — the
0.2.0 attempt sat queued for seven hours and never started. Neither reason
survives the change below.

Releases now ship four archives: x86_64 and aarch64, Linux and macOS.

## Your TLS runs on a different libcrypto

**zoxy now links OpenSSL 3.5.7, built from source by Zig and linked statically
into the binary.** Before, it linked whatever libcrypto the build machine
happened to provide — in practice nixpkgs' 3.6.3, resolved through pkg-config.

Same protocol, same code above it, different implementation underneath. If you
compare TLS numbers across this release, compare them knowing that.

3.5 is the LTS line, supported to April 2030. Relative to what the release
binaries linked before this is one minor version back, onto a branch with
long-term security support; 3.6.3 was measured and rejected because 3.6
restructured OpenSSL's provider tree far enough to make the port a project
rather than a bump.

The practical consequence beyond the new platform: libcrypto is now static on
*every* build, not just releases, and the binary carries no reference to the
machine that built it.

## Under the hood

- The release workflow can be rehearsed. `dry_run` builds every target,
  smoke-tests each binary on its own platform, packages and checksums exactly
  as a release does, then stops before publishing anything or touching the tap.
  Until now `release.yml` could only be tested by cutting a release, which is
  how 0.2.0 shipped without macOS.
- The `x86_64-macos` binary is cross-compiled on an Apple Silicon runner and
  then **executed there under Rosetta 2**, so the same "does it run, does it
  report the right version" gate the other three platforms get applies to it
  too.
- After a real release, the tag is checked for all four archives, the
  checksums and the config schema. A release that half-published now fails
  loudly instead of finishing green.

## Upgrading

Nothing to do. No configuration, CLI or behavioural changes.
