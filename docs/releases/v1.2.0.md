**zoxy 1.2: HTTP/3 to clients.** An `http` listener with `tls` may
name a QUIC binding, a UDP address, and serve HTTP/3 there with the
listener's own routes, filters, policies and certificates. Origins are
reached as before, over HTTP/1.1 or HTTP/2 as each cluster says. Every
answer the listener relays from an origin advertises the binding in
`Alt-Svc`, so browsers move over on their own.

A config without a `quic` binding needs nothing: replace the binary. It
serves what 1.1.0 served, but for one TLS refusal no TCP client meets,
and the new counters stay at zero.

## Serving HTTP/3

DESIGN §7's "HTTP/3 to clients" has the whole design, and §12 the
deviations.

### The config

```json
{ "bind": "0.0.0.0:443",
  "http": { "routes": [ ... ], "quic": { "bind": "0.0.0.0:443" } },
  "tls": { "cert": "...", "key": "..." } }
```

- **`http.quic.bind`** is a UDP address, an IP literal and a port, never
  `unix:`. It is usually the listener's own. QUIC is always TLS 1.3, so a
  listener without `tls` is refused (`ListenerQuicWithoutTls`). ALPN is
  `h3` alone.
- **`http.quic.alt_svc_max_age_s`**, default 86400, at most a year.
  - Every answer the listener relays from an origin, over TCP and over
    HTTP/3, carries `Alt-Svc: h3=":<port>"; ma=<age>`. It is set over the
    origin's own and takes one of the listener's response header edits.
  - zoxy's own answers carry none: a shed `503`, a static page, a
    policy's answer.
  - The port is the one bound, so a binding on port 0 advertises
    nothing. Behind a port mapping, set the age to 0 and write the field
    as a response filter of your own.
  - A listener whose response filters already use every header edit is
    refused (`ListenerQuicAltSvcOverEditLimit`); set the age to 0 or
    drop one.
- **`limits.quic_connections`**: the HTTP/3 connections served at once.
  - It defaults to 64, capped at `conn_slots` and `tls_engines`, and may
    exceed neither.
  - Each connection holds a TLS engine and a conn slot for its whole
    life, and costs ~835 KiB, priced in the banner.
  - The key is refused where no listener has a binding.
- **`limits.h2_streams`** is required with a QUIC binding, as with
  HTTP/2. HTTP/3's request streams run on the same shared stream pool.

### What it speaks

- **QUIC version 1** (RFC 9000, 9001, 9002), with NewReno congestion
  control.
- **HTTP/3** (RFC 9114), with QPACK's static table only: the dynamic
  table's capacity is zero.
- **A request** is downgraded to an HTTP/1.1 head and parsed back, as
  HTTP/2's are. Filters, policies, routing, the access log and
  Proxy-Status treat it like any other request.
- **Up to 8 request streams** per connection. A stream the pool cannot
  hold gets `H3_REQUEST_REJECTED`, which the client may retry. A body is
  read only as fast as its origin takes it: QUIC's stream window holds
  the client back.
- **Draining** sends GOAWAY, finishes the requests in flight and closes
  with `H3_NO_ERROR`.

### Admission

- **Connection policies** (#425) run on a new connection's first Initial,
  as on TCP.
- **Retry** under pressure. Once the pool is half full, a new client is
  sent a Retry first, so it proves its address. The token is a MAC over
  the client's address, its original connection ID and the time, and is
  good for ten seconds.
- **Version Negotiation** answers an unknown version.
- **A stateless reset** answers a short-header packet no connection
  holds. It is always shorter than its trigger.

### Limits of this release

- **No 0-RTT.** No session ticket is issued over QUIC. A ticket a TCP
  connection issued still resumes a QUIC handshake, without early data.
- **No connection migration.** The server advertises
  `disable_active_migration` and drops a connection's datagrams from any
  other address (`h3_migration_dropped`). A NAT rebinding therefore ends
  the connection. Path validation is #453.
- **One process per UDP port.** The kernel spreads a `SO_REUSEPORT`
  port's traffic per datagram, not per connection, so a client whose NAT
  rebinds would land on a process with no state for it. The QUIC socket
  is therefore bound without `SO_REUSEPORT`, and a second process asking
  for the port is refused at start. Steering by connection ID is #452.
- **No QUIC past the edge.** There is no HTTP/3 to origins and no L4
  QUIC pass-through.

## The stock binary

- **The banner.**
  - It gains a line, `h3 connections`, `quic endpoints` and
    `h3 scratch`, which reads `0 x 0 B` and `0 B` without a QUIC binding.
  - Slots grow for the fields a QUIC connection and its streams keep:
    conn slots 576 → 600 B, stream slots 1896 → 1904 B.
  - A TLS engine grows 95,200 → 96,304 B for QUIC mode: its flight
    scratch rises to zssl's QUIC floor, it keeps a copy of the transport
    parameters, and zssl's handshake state grows. Every engine carries
    it, whether or not it serves QUIC.
- **TLS over TCP** refuses a ClientHello carrying QUIC's transport
  parameters (extension 57) with `unsupported_extension`, as RFC 9001
  §8.2 requires. No TCP client sends one.
  - The labeled-metrics figure rises for the new counters' rows: 39,662
    → 42,626 B on a one-listener, one-cluster config.
- **Metrics.** 18 new counters, listed under Upgrading, each rendered at
  zero without a QUIC binding.
- **The JSON Schema** gains `http.quic` (`bind`, `alt_svc_max_age_s`)
  and `limits.quic_connections`.
- **The counter identity** reads `admitted + h3_admitted == completed +
  active`. A QUIC connection is admitted without being accepted: it has
  no socket of its own.

## Checked against

- **The gates.** Every change passed the unit and fuzz corpus, the lint,
  4,096 simulator seeds with the census, and the live gate in both the
  default and the shipped ReleaseSafe build.
  - The live gate gained an HTTP/3 leg: three requests on one connection
    to the shipped binary, on a real kernel.
- **The simulator.**
  - A seed whose TLS listener speaks HTTP draws a QUIC binding half the
    time, and one or two HTTP/3 clients. Their datagrams meet a new
    adversary: dropped, duplicated, delayed past their successors,
    corrupted, and sent from a rebound port.
  - The census: 128 counters fired, 51 exempt; 23 extension counters
    fired; 12 seam operations, 1 exempt.
- **h3spec** 0.1.15: 86 cases, none failed, and one pending, the 0-RTT
  case §12 records.
- **h2spec.** It matched DESIGN §12's recorded deviations: 145 cases
  over h2c with 1 recorded failure, and 145 over TLS with none.
- **curl over ngtcp2 and nghttp3**, by hand:
  - a 2 MiB download, byte-identical;
  - a 200 KB upload, checked octet for octet;
  - 20 requests multiplexed on one connection;
  - 12 parallel connections, 8 served and 4 shed by the configured pool.
- **The soak found a hang, and this release carries its fix** (#459).
  - The case: a client sent one Initial and fell silent once the
    server's flight had spent its address's amplification budget. The
    server then drained mid-handshake and closed the connection, with
    nothing it could send. The closing period never started, and the
    connection's timer fired at the same instant forever. About one
    seed in 20,000 hit it. In production, a drain would have spun a core
    until its deadline.
  - The simulator now prints its progress and names a seed that never
    ends (#458), which is how the soak found it. A night is now 8 shards
    of 500,000 seeds, because HTTP/3's seeds cost about 28% more (#457).
  - The soak also showed four of the simulator's own assumptions were
    too strict at its scale, and all are corrected (#460 to #463):
    - Version Negotiation does fire, rarely, on a datagram corrupted in
      its version field.
    - A clean seed's age cap may cut an HTTP/3 request, as it may on
      TCP. Both the request oracle and the access log's rule now excuse
      exactly that cut, client by client.
    - A seed with HTTP/3 clients can log more lines in one burst than
      the smallest access-log staging holds. Such seeds now stage at
      the default.
    - A retry that straddles an endpoint-set update can meet two
      refusing endpoints, so a seed now churns its endpoints only when
      its retry budget is two or more.
  - Then a run on this release's code passed: 8 × 500,000 seeds,
    568,000,001 to 572,000,000, census ok in every shard,
    [run 44943000068](https://github.com/zoxy-io/zoxy/actions/runs/44943000068).
    Later commits change only the version, these notes, and
    docs/README.md's version strings and sample banner. The simulator
    runs none of them.
- **The bench.** Tier 1 against nginx, beside haproxy: zoxy's bands
  match 1.1.0's, its keep-alive p50s within 2 µs on every row. The
  resident set stayed flat across the run, under its budget.

## Upgrading

Replace the binary. A config 1.1.0 loads, 1.2.0 loads the same way.

A build on the library moves with the seam:

- **`Options`** gains `Listener.Http.quic` (`?Options.Listener.Quic`,
  default null) and `Limits.quic_connections` (`?u32`, default null). Struct
  literals need no change.
- **The `Io` seam** gains datagrams. A backend of a build's own,
  checked by `assertIoInterface`, must now declare `UdpSocket`,
  `DatagramCompletion`, `udpBind`, `udpAddress`, `recvFrom`, `sendTo`,
  `datagramCancel` and `udpClose`. `XevIo` and `SimIo` do.
- **New exports.** `zoxy.XevIo`, for a tool that drives the seam on a
  real kernel outside the server, as the live gate's HTTP/3 client does,
  and `zoxy.http.h3.TestClient`, the HTTP/3 client the simulator and that
  gate use.
- **`App.serve`'s error set** gains the new startup refusals:
  - `ListenerQuicWithoutTls`
  - `ListenerQuicBindNotIp`
  - `ListenerQuicBindDuplicate`
  - `ListenerQuicAltSvcMaxAgeOutOfRange`
  - `ListenerQuicAltSvcOverEditLimit`
  - `LimitQuicConnectionsOutOfRange`
  - `LimitQuicConnectionsOverConnSlots`
  - `LimitQuicConnectionsOverTlsEngines`
  - `LimitQuicConnectionsWithoutQuic`

A dashboard that reads active connections as `admitted - completed`
counts QUIC's apart: active is `admitted + h3_admitted - completed`.
`accepted` counts TCP alone.

New counters, every one at zero without a QUIC binding:

- `h3_admitted`, `h3_handshakes`, `h3_idle_closed`
- `h3_shed_connections`, `h3_shed_tls_engines`, `h3_shed_tls_crypto`,
  `h3_shed_streams`
- `h3_protocol_errors`, `h3_qpack_failures`, `h3_malformed_requests`,
  `h3_events_overflowed`
- `h3_packets_lost`, `h3_datagrams_dropped`, `h3_migration_dropped`
- `h3_version_negotiations`, `h3_retries`, `h3_tokens_refused`,
  `h3_stateless_resets`
