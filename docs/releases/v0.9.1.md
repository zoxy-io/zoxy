**A toolchain release: zoxy is now built with Zig 0.17.1.** Nothing in
your config has to change, and nothing the proxy does should either. The
shipped binary prices every budget and emits every schema key exactly as
0.9.0 did.

## Same proxy, new compiler

Zig 0.17 removed or reshaped enough of the language (`**` array
repetition, the layout of `@typeInfo`, several builtins) and of the build
system that 0.9.0's source no longer compiles on it. Every pinned
dependency had to move to a 0.17 commit along with it. This release is
that move, checked against the release before it:

- `zoxy --check` prices the example config and a TLS-terminating one
  line for line as 0.9.0 does: memory, fds, ring, and the per-engine
  `94448 B`. No §5 budget moved.
- The config JSON Schema is byte-identical to 0.9.0's.
- `zig build ci` is green: unit tests and the fuzz corpus, the boundary
  lint, simulation, and the live gate against both the default build and
  the ReleaseSafe build this release ships.

## What moved underneath

- **libxev** now sits on upstream's own Zig 0.17 port, with the fork's
  six commits replayed onto it unchanged. `git range-diff` shows each one
  identical to what was audited, and upstream's port touches tests and
  compile-time reflection, not an event-loop backend.
- **hparse**'s 0.17 commit respells two default values and changes
  nothing else zoxy links. The parser accepts and refuses exactly the
  bytes it did.
- **zssl** moves six commits. One is on the serving path: the server
  handshake now encodes the order of the client's second flight in its
  state type instead of rebuilding it from flags (RFC 8446 Appendix
  A.2). zoxy asks for no client certificates, so its handshakes take
  the same transition they always did, and no alert changes. The rest
  harden zssl's *client*, which zoxy reaches only from its tests, and
  port its build.
- **zrk**, the load generator behind `zig build bench`, moves to v3.0.1,
  with zio v0.20.1 in lockstep. It is never linked into the proxy. Local
  bench bands are still not comparable to the nightly fleet, which runs
  zrk v2.4.2.

Each move carries its re-audit record in `build.zig.zon`.

## Under the hood

- The boundary lint is now built ReleaseSafe. 0.17's default Debug
  backend stretched it to minutes, the slowest gate in `zig build ci`. It
  now runs in about a second, with assertions still on.
- `build.zig` now tells 0.17's new configure cache when it reads the
  environment or runs `git describe`, so a stale build id is never
  replayed into `zoxy --version`.
- Coverage-guided fuzzing (`zig build test --fuzz`) can run for the first
  time; 0.16's test runner could not build it. Its first run found that
  the incremental head parser and its whole-head oracle disagree about a
  malformed head with no terminator. Fed in pieces, such a head is not
  refused until the head buffer fills (as a 414 or 431) or the client's
  deadline passes. A whole-head parse refuses it at once with a 400. That
  was 0.9.0's behaviour too and is unchanged here; fuzzing stays out of
  the gates until the two agree.
- Since 0.9.0: two simulator and nightly-soak fixes (#342, #343). Neither
  changes the binary.

## Upgrading

Replace the binary. Nothing else.

Building from source now needs Zig 0.17; the devenv shell pins 0.17.1,
and 0.16 no longer builds this tree. `-Doptimize` takes the new
spellings, `safe` and `fast`. The old `ReleaseSafe` and `ReleaseFast`
still parse, deprecated until after Zig 0.18.
