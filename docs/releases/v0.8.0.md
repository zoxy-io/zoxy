**This release breaks every config.** The pre-1.0 config freeze (#305)
landed, so a listener declares its protocol as the key of its own body
rather than as a string beside eleven flat fields. Read the upgrading
section before rolling it out — `zoxy --check config.json`, new here, will
tell you in a second whether yours still parses.

It is also the largest feature release so far: L4 SNI routing, header
routing, `Proxy-Status`, Unix-domain sockets at both ends, RED metrics, a
config schema, a watchdog for a stalled event loop, and a TLS 1.3 engine
written for this proxy rather than borrowed.

## Upgrading

### A listener names its protocol with a key, not a string

```json
{ "bind": "0.0.0.0:443",
  "tls":  { "cert": "…", "key": "…" },
  "http": { "routes": [ … ], "max_body_bytes": 1048576 } }

{ "bind": "0.0.0.0:5432",
  "l4":   { "cluster": "postgres" } }
```

`protocol` is gone, and so is its old default of `"l4"` — absence reading
as "relay blindly" is the wrong way for a reverse proxy to guess, and a
freeze is the last moment that can change. `bind` and `tls` stay outside
the body because both protocols share them. Everything else moved into
the body that gives it meaning, which is why `{"l4": {"max_body_bytes":
500}}` is now an unwritable config rather than a rejected one: eight
loader errors are deleted instead of reworded.

### `upgrades` is a set of flags

```json
"upgrades": ["websocket"]        →  "upgrades": { "websocket": true }
```

The vocabulary was always closed — `h2c` would tunnel HTTP/2 to an origin
that cannot parse it — and a list of strings can only be closed by the
loader, in rules a reader of the schema never sees. Duplicates stop being
expressible at all.

### `keepalive_requests` moves from `limits` to `http`

```json
"limits": { "keepalive_requests": 1000 }  →  "http": { "keepalive_requests": 1000 }
```

`limits` sizes what the process reserves at startup. This bounds what one
client may occupy, reserves nothing, and was the standing exception to a
rule §5 now states outright.

### SIGUSR1 no longer prints counters

It is ignored rather than handled, so muscle memory costs nothing — but
nothing is printed either. `/metrics` on the admin listener serves the
same exposition, framed and scrapeable, and a drain still prints the final
tally. The dump was a synchronous write that reached 1.6 MB on a large
config, and one of them on a slow pipe parked the event loop for as long
as the reader took (#310).

### Everything else

Replace the binary. `--check` prices a config against the box it will run
on — pools, fds, ring depth, `RLIMIT_NOFILE` — without taking a port, so a
config can be validated in CI and on the target before a restart:

```
$ zoxy --check config.json
zoxy 0.8.0
budgets (DESIGN.md §5/§8; closed-form except where marked):
  memory  total 47286 KiB = conn slots 1386 x 512 B + stream slots 1386 x 1544 B
  …
  check   config.json: valid, and this box can start it
```

Exit 0 means valid and startable here; 1 means the loader refused it and
says which rule.

## Routing

- **L4 SNI routing** (#298). One `:443` fronting many backends while
  terminating nothing: the listener reads the ClientHello's server name,
  routes on it, and relays the handshake untouched. The client's
  certificate check still happens against the origin, because zoxy never
  had the key.
- **A route may match a header** (#302), so a pinned canary has an
  expression rather than a percentage:

  ```json
  "routes": [
      { "header": { "name": "X-Canary", "present": true },
        "prefix": "/", "cluster": "next" },
      { "prefix": "/", "cluster": "stable" }
  ]
  ```

  `{"present": true}` for any value or `{"equals": "…"}` for one; names
  match case-insensitively per RFC 9110, values do not. Host, then header,
  then prefix — every key a route states must hold.

## Observability

- **Errors and Duration**, not only Rate (#299).
  `zoxy_cluster_responses{cluster,class}` and a standard Prometheus
  histogram, `zoxy_cluster_duration_seconds`, so `histogram_quantile`
  works on it directly and the R-E-D triad is answerable from `/metrics`
  alone. An origin's 5xx used to be invisible.
- **`Proxy-Status`** (RFC 9209) on responses zoxy generates (#300). A shed
  `503` and an origin's `503` are different facts, and the wire could not
  tell them apart; now `Proxy-Status: zoxy; error=connection_limit_reached`
  says which rung answered. An upstream proxy's own field survives — it is
  a List, and zoxy appends.
- **A JSON Schema for the config** — `zig build schema` emits it, and a
  gate holds it to the loader in both directions, so an editor that reads
  the schema and the binary that reads the config now agree by
  construction rather than by review.

## Reach

- **Unix-domain sockets at both ends** (#303). `"bind": "unix:/run/zoxy.sock"`
  for a listener, `"endpoints": ["unix:/run/app.sock"]` for a cluster. An
  address stays a string; the `unix:` prefix extends its grammar rather
  than making the two most-written fields in any config polymorphic.

## Resilience

- **A watchdog for a stalled event loop** (#311). Every deadline zoxy owns
  is a timer the loop delivers, so none of them can bound the loop itself
  — a loop parked in a blocking call delivers nothing, including the timer
  that would have reported it, and what you see is a process that is
  alive, passing health checks, holding its listeners and answering
  nothing. `"timeouts": {"loop_watchdog_ms": 5000}` gives the kernel a
  bound the loop cannot silence: the process writes one line to stderr and
  exits **6**, so a supervisor replaces it. Off unless you name a number.
- **macOS: a stalled loop under load** (#314). A libxev `kqueue` bug could
  cross two intrusive lists and spin a core forever with both listeners
  dead and SIGTERM undeliverable. Fixed in the audited fork; upstream has
  the same defect open as two issues.

## TLS

The engine is **zssl** now (#322, #327) — a TLS 1.3 protocol layer written
for this proxy over libcrypto's primitives, replacing the audited `ztls`
fork whose five carried patches were all fixes this codebase needed and
upstream had not taken. What that buys is an adversarial test surface the
borrowed engine never had: BoGo (BoringSSL's hostile-peer runner, 454
cases against a floor), tlsfuzzer driving the server, and TLS-Anvil's
RFC-derived corpus, each holding a counted floor so a regression or a
quiet suppression fails the build.

What those found and this release ships: bounds on consecutive empty
records, KeyUpdates and warning alerts — all legal, all free for a sender,
all unbounded work for the proxy before this — RFC 8446 §5.4's
inner-plaintext cap, an alert for a record refused at its header, and a
framing pre-pass that closes a remote abort in `std.crypto.Certificate`.
The server also does one scalar multiplication per handshake instead of
two.

## What it costs

An admitted connection is a conn slot **and** a stream slot now (#274),
which is what makes an exchange's state a thing the connection lends
rather than owns. Same deployment, default limits, priced by the binary
itself:

    0.7.0   47010 KiB   conn slots 1386 x 1856 B
    0.8.0   47286 KiB   conn slots 1386 x  512 B + stream slots 1386 x 1544 B

+200 B per admitted connection, and ~5 KiB more for the metric tables the
new families need — +0.6% on that deployment. A TLS listener pays a
further 880 B per engine, which is the new engine's own state. The ring
budget gains exactly one op, for the watchdog's tick, whether or not you
arm it.

Nothing about relay buffers moved, so 0.7.0's memory advice still stands
unchanged.
