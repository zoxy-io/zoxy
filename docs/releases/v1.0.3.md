**A peer's certificate can no longer stop the process.** In 1.0.0 to
1.0.2, some RSA keys made zoxy panic during the handshake: a modulus of
8k+1 bits, such as 3065. The peer was a mutual-TLS client or an HTTPS
origin holding such a key in a certificate from a CA you configured. The
panic ended every connection the process held. 1.0.3 refuses such a key,
and the handshake fails like any other.

## Fixes

- **A peer's RSA key of 8k+1 bits is refused instead of stopping the
  process.** In the handshake, zoxy checks the peer's signature against
  its certificate. That covers a client under a listener's `client_ca`
  and an HTTPS or h2 origin under its cluster's `ca`. For an RSA key, the
  check went through `std.crypto`'s RSA-PSS verifier. That verifier
  asserts that the signed message fills the key's width in bytes. For a
  modulus of 8k+1 bits (1017, 2041, 3065 or 4089) it is a byte short
  (RFC 8017 §8.1.2). zoxy ships with assertions on, so the assertion
  stopped the process.

  It took a certificate that chains to an anchor you configured, because
  the chain is checked before the signature. An anonymous client could
  not reach it, and a listener without `client_ca` asks no client for a
  certificate. But one handshake was enough.

  zssl, the TLS layer zoxy pins, now refuses such a key before it
  verifies (zoxy-io/zssl#23). Each kind of peer now fails the way any
  failed handshake does:
  - a client gets the bare teardown and is counted in
    `zoxy_tls_handshake_failed`;
  - an HTTPS origin's request answers `502` and counts in
    `zoxy_upstream_tls_failed`;
  - an h2 origin's connection counts in `zoxy_h2_origin_tls_failed`.

## Under the hood

- **zssl moves from 5f5c582 to 69fa0aa**, one commit: this fix and its
  tests. The re-audit is recorded beside the pin in `build.zig.zon`.
  `zoxy --check` prints the same budget as 1.0.2.

## Checked against

- **The gates.** The change passed the unit and fuzz corpus, the lint,
  the libcrypto heap proof, 4,096 simulator seeds with the census, and
  the live gate in both the default and the shipped ReleaseSafe build.
- **The tests.** One engine test has a mutual-TLS client present a
  3065-bit RSA leaf that its CA issued. One origin-client test has an
  origin serve that leaf. On 1.0.2's zssl, both stopped at the
  assertion. Now both handshakes fail with `BadCertificate`. zssl's own
  tests drive a key of the same size from both sides of a handshake.
  Its gates passed: tests 180/180 in Debug and ReleaseSafe, interop on
  all five legs, BoGo 454 at its floor, tlsfuzzer 22/22, and TLS-Anvil
  115 at its floor, on zoxy-io/zssl#24.
- **The soak.** A run on this release's code passed: 4 × 1,000,000
  seeds, 520,000,001 to 524,000,000,
  [run 44731599529](https://github.com/zoxy-io/zoxy/actions/runs/44731599529).

## Upgrading

Replace the binary; no config changes. Nothing that worked stops
working: no zoxy configuration ever completed a handshake with such a
peer. It stopped the process instead.
